---
title: 多地址导航（Fork 扩展）
description: 在 kanon-H/homepage 中按网络模式切换服务导航地址
---

这是 **kanon-H/homepage Fork** 的可选扩展，不是官方 Homepage 的配置承诺。旧配置不需要迁移；未启用时保留原有导航行为。

同一个服务可以有默认、内网、VPN 等地址。首页右上方选择当前模式后，服务图标、标题和服务搜索结果一起更新；服务的右键/更多菜单可以临时打开其他地址，而不改变全局选择。

> 当前已完成组件、生产实例及 Chromium 自动化回归；仍有人工原生浏览器、物理触屏和目标部署环境检查未完成。这不是完整 v1 验收、发布或生产部署声明。

## 1. 配置

先备份自己的 YAML。以下域名和 `192.0.2.0/24` 地址仅用于说明，必须换成浏览器实际可访问的地址。

在 `settings.yaml` 增加（保留其他设置）：

```yaml
extensions:
  network:
    enabled: true
    defaultMode: default
    modes:
      - id: default
        label: 默认
      - id: lan
        label: 内网
      - id: vpn
        label: VPN
      - id: office
        label: 公司网络
```

在 `services.yaml` 的服务项中增加 `extensions.network.addresses`：

```yaml
- 基础设施:
    - NAS:
        href: https://nas.example.invalid/
        icon: mdi-server
        description: 文件管理
        extensions:
          network:
            addresses:
              lan: http://192.0.2.10:5000/
              vpn: http://192.0.2.20:5000/
    - 普通服务:
        href: https://status.example.invalid/
```

保存后使用 Homepage 页脚的刷新按钮清除配置缓存并重新加载。**不会由模式切换自动修改或保存 YAML。**

上述配置中：

- `default` 始终使用原始 `href`。不要配置 `addresses.default`。
- 选择“内网”或 VPN，NAS 使用对应备用地址；普通服务仍使用原始地址。
- 选择“公司网络”，NAS 因未配置 `office` 而回退原始地址，菜单提示当前使用默认地址；不会出现虚假的公司网络地址菜单项。
- `defaultMode: lan` 可将无有效浏览器偏好时的初始模式改为内网；它不会重新定义“默认地址”。已有合法本地偏好优先。
- `default` 可省略，程序会补齐并放在首位；其他模式遵循配置顺序。只有默认模式时不显示切换器。
- `enabled` 可省略，合法 network 对象存在时默认启用；仅在服务上写备用地址不会自动启用全局扩展。

## 2. 日常使用

### 全局模式与搜索

切换器在首页顶部右侧；即使没有信息 Widget 也会出现。切换后无需整页刷新，图标和标题是当前模式的真实链接，保留中键和 Ctrl/Cmd 等浏览器原生操作。目标窗口仍按服务 `target`、全局 `target`、`_blank` 的顺序决定。

服务搜索使用同一个模式。搜索面板已打开时，其他同 origin 标签页改变模式，当前结果也会更新。普通书签、搜索引擎、搜索建议和直接输入 URL 不应用多地址规则；在书签里配置这个扩展也不会生效。

### 临时打开与复制

有合法备用地址的服务在图标/标题右键可打开地址菜单，也可点击卡片上的“…”按钮。手机请使用可见按钮，不依赖长按。

- 菜单包含默认地址及该服务有效的备用地址，并标记当前来源。
- 从菜单打开其他地址只影响这一次导航，不切换全局模式、不保存偏好。
- 不同模式使用相同 URL 时仍保留各自菜单项。
- 右键只接管图标/标题，不接管 Widget、监控/统计或整张卡片。
- Shift+右键不主动阻止浏览器原生菜单；具体原生界面由浏览器/操作系统决定。
- 更多按钮支持 Enter/Space、上下方向键；菜单支持方向键循环、Home/End、Escape、Tab。Escape 关闭后返回触发器；页面滚动、窗口调整、点击外部或模式变化也会关闭菜单。
- “复制当前地址”需要安全上下文和 Clipboard API 权限；失败会提示错误，不会自动跳转。生产使用 HTTPS。localhost 在浏览器中可能被视为安全上下文，不能用 localhost HTTP 的复制成功证明普通 HTTP 可用。

### 浏览器偏好

同一浏览器 origin 保存：

```text
homepage.network.preference.v1
```

```json
{ "version": 1, "mode": "lan" }
```

只保存模式 ID，不保存 URL、服务列表或认证信息。同 origin 标签页同步；不同设备、域名或端口不共享。退出登录不会清除此偏好，同 origin 的多个 Homepage 实例会共享这个 key。

显式切换才保存；恢复时不会覆盖旧值。损坏 JSON、不支持的版本或已删除模式会回退配置默认。扩展的存储读取/写入失败会安全降级为内存切换；这不是对上游其他主题/颜色等功能在全站存储被禁时的兼容保证。

若只想重置网络偏好，可在当前站点的浏览器开发工具中删除此 key，或在该站点控制台执行：

```js
localStorage.removeItem("homepage.network.preference.v1");
```

不要为重置模式而清空整个站点数据，以免顺带删除登录状态或其他偏好。

## 3. 配置限制与排错

| 现象                            | 检查                                                                                                    |
| ------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 没有切换器                      | 全局路径是否为 `extensions.network`；是否显式禁用、结构非法，或只有内置默认模式；保存后是否刷新配置缓存 |
| 服务没有更多按钮                | 是否有可用原始 `href`，且至少一个备用地址合法并属于全局已定义模式                                       |
| 某模式仍打开默认地址            | 该服务缺少该模式地址或地址校验失败；这是局部回退，不是自动探测结果                                      |
| 变更 `defaultMode` 后仍选旧模式 | 已有合法浏览器偏好优先；手动切换或仅删除网络偏好 key                                                    |
| 暂时无法点击某服务              | 首次恢复偏好前，有备用地址的服务短暂禁用导航和菜单，避免误开默认地址；普通旧服务及书签不等待            |
| 菜单复制失败                    | 使用 HTTPS，检查浏览器 Clipboard API 支持及权限；可用浏览器原生复制链接功能作为手动替代                 |
| 浏览器能打开应用但 Widget 报错  | Widget 由 Homepage 后端连接，URL/认证单独配置，不随导航模式变化                                         |
| 配置有误却没有阻断首页          | 扩展语义错误非致命；查看服务端脱敏警告。`/api/validate` 不承诺检查全部扩展语义                          |

模式 ID 必须满足 `^[a-z][a-z0-9_-]{0,31}$`，不会自动转小写或去空格；显示标签去首尾空白后为 1～64 个 Unicode 码点。标签按文本显示，不执行 HTML。重复 ID 保留第一个合法条目。

备用地址只接受绝对 `http://` / `https://` URL；允许端口、IPv4/IPv6、路径、query 和 fragment，不探测可达性。禁止相对地址、脚本/文件协议、URL 内嵌用户名密码及 ASCII 控制字符。空/null 视为未配置；未知模式、`addresses.default` 和非法地址忽略并给出脱敏诊断。原始旧 `href` 不因该扩展被收紧协议或改写。

没有原始 `href`、空白或仅 `#` 的服务不会因备用地址而变成可导航服务。嵌套分组使用相同规则；v1 不新增 Docker labels/Kubernetes annotations 的专门配置语法。

## 4. 安全与边界

- 模式只是导航选择，**不是权限控制**。已登录浏览器能看到全部合法候选地址；未开启上游认证时，不应将内网地址列表视为秘密。
- 继续使用 Homepage 原生密码/OIDC；不增加账户管理、数据库或服务端偏好接口。
- 配置只交给可信管理员。不要在任何导航 URL 的 query 中保存 token；禁止在备用 URL 内保存账号密码。真实配置、密钥和 Cookie 不进 Git、截图或 Docker context。
- 模式不改 Widget URL/密钥、ping/siteMonitor、Docker/Kubernetes/Proxmox 连接、Homepage 登录回调或自身 canonical URL。
- 不自动判断网络，不后台探活，不将应用请求代理经过 Homepage。浏览器自身必须能连通所选地址。
- 偏好恢复需要 JavaScript；关闭 JavaScript 时，可扩展服务没有可导航链接，普通旧服务仍按原行为。
- 反代/CDN 必须尊重认证响应的 `private, no-store`，不得强制缓存登录 HTML、Next 页面数据及服务 API。修改缓存规则后应使用独立匿名客户端重新验证，不能只看登录客户端能打开。
- 当前通过的是受控 localhost HTTPS/nginx 缓存测试，不代表你的生产代理、CDN、OIDC 或所有浏览器已经验收。部署前仍需人工检查原生右键/Shift、目标设备和目标环境。

### 当前已知手机兼容差异

人工测试中，华为浏览器（鸿蒙6）报告新标签打开；红米小米浏览器 `v20.28.1020918`，以及红米/鸿蒙手机上的 QQ 浏览器，报告即使请求 `_blank` 仍替换当前页。用户已用标签列表确认不是仅新标签切前台；标题和菜单地址均有该现象，更多按钮本身只展开菜单。

测试配置及已检查的页面链接确实为 `_blank`，但尚未在这些实际浏览器中确定原因；**该问题未解决，排查已由用户暂停**，不能据此宣称完整手机验收通过。目前保留原版 target 继承与真实链接，不以强制 JavaScript 弹窗、移除安全 rel 或关闭浏览器保护作为未经验证的修复。

## 5. 关闭与回退

将 `settings.yaml` 中的配置改为：

```yaml
extensions:
  network:
    enabled: false
```

保留其他 settings/extensions 字段，刷新配置缓存。也可以只移除全局 network 配置。关闭后全部服务回到原始 `href`，无切换器、菜单和网络偏好读写；旧偏好不被删除，将来重新启用时可恢复仍合法的模式。书签、Widget 和原生认证保持不变。

完整行为合同与验收方法见仓库根目录 `SPEC.md`、`DEVELOPMENT.md`；剩余设备与目标环境检查可使用[人工验收记录模板](../more/network-acceptance.md)。关闭扩展不等于降级镜像，也不授权自动部署或关闭认证。
